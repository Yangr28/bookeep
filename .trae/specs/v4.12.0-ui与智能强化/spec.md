# v4.12.0 UI 全站精修与智能强化 - 产品需求文档

## Overview
- **Summary**: 在现有"暖纸·青蓝"设计体系上对全部高频页面做一致性精修，并强化四块智能能力：更聪明的分类/账户预测、连续记账与快捷输入、月度智能洞察报告、语音记账。
- **Purpose**: 提升日常记账速度（更少点击、更少选分类）、让数据"会说话"（自动发现异常与固定支出），同时统一全站视觉品质与深色模式表现。
- **Target Users**: 已在使用 bookeep 的个人记账用户（中文/英文双语，Android 端为主，Web 端降级可用）。

## Goals
- 记账前：系统基于历史行为主动推荐分类、账户、金额，输入时给出可点选的补全候选。
- 记账中：支持"保存并继续"连续记账，语音直接转一句话记账。
- 记账后：每月自动生成可读的智能洞察（环比异常、超支风险、大额支出、固定/订阅支出、高频消费）。
- 视觉上：全站在现有设计令牌体系内完成精修，信息层级、间距、空状态、加载态、微交互统一，深色模式完整适配。

## Non-Goals
- 不替换现有设计语言（不引入毛玻璃、重渐变、大角度 3D 特效）。
- 不做云端/服务端 AI、LLM 接入；全部"智能"均为设备端基于本地数据的确定性规则算法。
- 不做周期记账引擎重做与余额对账（顺延至 v4.13.0）。
- 不做年度账单/资产净值曲线（路线图 v4.15.0）。
- 不做 iOS 端发版与原生桌面小部件。
- Web 端不提供语音能力（无原生桥），仅隐藏入口。

## Background & Context
- 技术栈：React 18 + Zustand 5 + Vite 6 + TailwindCSS + Capacitor 8 + react-i18next（中/英）。
- 设计令牌集中在 `src/index.css`（:root/.dark 双套 CSS 变量 + @layer components 组件类），tailwind.config.js 扩展色板与圆角阴影；美化必须在此体系内做"调参/补齐"，禁止新造平行色值体系。
- 已有智能能力：`parseSmartInput`/`parseSmartInputWithHistory`（`src/utils/smartParser.ts`）支持自然语言→金额/分类/账户/日期时间；首页一句话记账三要素齐全可秒存；OCR 拍照识别已有。
- 已发现的缺陷与债：
  1. `parseSmartInputWithHistory` 统计了商家→分类频次但未把命中分类写回结果（仅加置信度），历史匹配实际不改变推荐结果。
  2. `src/components/NumericKeypad.tsx` 为死代码（无任何引用），且硬编码中文、gray-* 色值与渐变，脱离令牌体系。
  3. 全站缺少骨架屏组件，列表加载/首屏期间多为空白或单次 spinner。
- 语音：Android System WebView 不保证支持 Web Speech API；可靠路径是 Capacitor 原生语音插件（系统 RecognizerIntent，需 RECORD_AUDIO 权限，依赖设备上的语音服务/可能需联网），故 v4.12.0 必须发整包 APK（versionCode 95）。
- 版本规划：本需求插队为 v4.12.0；原"数据正确性下（周期记账引擎+余额对账）"顺延 v4.13.0。

## Functional Requirements

### FR-1 智能推荐引擎（纯逻辑）
- 新增设备端推荐模块（`src/utils/recommender.ts`），基于用户历史流水输出：
  - 高频分类排行（支持按收支类型过滤、近期记录加权、时间衰减）。
  - 给定上下文（备注关键词、商家、时段、星期）的最优分类预测及置信度。
  - 账户推荐（最常用/最近使用）。
  - 常用金额候选（历史高频金额）。
- 修复 `parseSmartInputWithHistory`：历史商家/备注命中分类时必须实际返回该分类，而不是只调置信度。
- 所有推荐为纯函数、确定性输出，可单测；不发网络请求。

### FR-2 记账页智能化
- 新增记账进入时，分类网格按推荐顺序排列，最常用分类置前并有"常用"视觉标识；当上下文足以预测时预选分类与账户（用户手动选择始终覆盖预选）。
- 金额区提供"常用金额"快捷 chips（横向，来自 FR-1 高频金额），点击直接填入。
- 分类网格与 chips 在浅色/深色模式下均符合令牌体系。

### FR-3 首页智能输入补全
- 首页一句话输入框在用户输入时（防抖）展示补全候选下拉：来自历史备注/商家的高频文本，点击整条填入；候选与已输入前缀匹配。
- 候选列表键盘可操作（移动端可点选即可），不遮挡首页保存入口。

### FR-4 连续记账
- 记账页新增"保存并继续"操作（与"保存"并列的次级/长按或开关形式，具体形式在设计阶段定，但必须醒目可达）。
- 连续模式保存后：停留在记账页，清空金额/备注/分类预选为下次推荐值，保留账户、收支类型与日期为今天；显示成功反馈。
- 编辑模式下不显示连续记账入口。

### FR-5 月度智能洞察（纯逻辑 + 展示）
- 新增纯逻辑模块（`src/utils/insights.ts`），对指定月份生成结构化洞察，至少包含：
  - 支出总额环比异常（较上月变化幅度超过阈值，默认 ±30%，上月支出为 0 时不报异常）。
  - 预算超支/临超支（结合预算数据与当月已过天数）。
  - 预计月末超支（当月日均支出×当月天数 > 月预算，无预算则不展示该项）。
  - 大额支出（单笔金额 ≥ 当月支出日均的 5 倍，列出前 3 笔）。
  - 固定/订阅类支出识别（同分类、金额近似（±5%）、最近 3 个月中至少 2 个月出现的周期性支出）。
  - 高频消费提示（某分类当月笔数 ≥ 8 笔，如"外卖 12 笔"）。
- 每条洞察含：类型、严重级别（info/warning/danger）、标题、描述、关联金额（可选）、点击可跳转关联流水/分类（固定/大额类）。
- 洞察卡片展示在"我的"页月度报表区域内（Profile.tsx 月度报表附近），无洞察时显示克制的空态，不硬凑内容。
- 数据不足（当月流水少于 5 笔或上月无数据）时相关规则静默不输出。

### FR-6 语音记账（原生）
- 接入 Capacitor 语音识别插件（实现阶段先验证与 Capacitor 8 的兼容性，不兼容则切换到持续维护的等价分叉），语言跟随应用语言（zh-CN/en-US）。
- 首次使用走运行时麦克风权限申请，被拒后给出解释与设置引导，不崩溃。
- 首页与记账页智能输入区提供麦克风按钮：点击开始识别，录音浮层展示监听状态与实时（partial）识别文本，再次点击/静音超时自动停止；识别文本进入现有一句话解析管道（FR-1/smartParser），用户确认前不直接入账。
- 设备不支持语音服务、Web 环境、旧基座（无原生方法）三种情况均优雅降级：隐藏或禁用麦克风入口并给出说明，不影响其他功能。

### FR-7 UI 全站精修
- 在现有令牌体系内统一全站：间距与信息层级、卡片/列表/按钮按压与焦点态、空状态、加载骨架屏、toast/弹层动效、列表入场节奏（stagger）。
- 覆盖页面：首页 Dashboard、记账 Record、明细 Statistics/AllRecords、交易详情 TransactionDetail、统计 Stats、我的/月报 Profile、账户 Accounts/AccountDetail、预算 Budgets、设置 Settings、模板 Templates、周期 RecurringRecords、搜索 Search、转账 Transfer、汇率 CurrencyConverter。
- 清理：移除 NumericKeypad 死代码；消除新增/既有改动面内的硬编码颜色（gray-*/内联 hex）与未走 i18n 的可见中文。
- 保持紧凑高密度风格，不增加记账关键路径的点击步数。

## Non-Functional Requirements
- **NFR-1 质量门禁**：tsc 通过、ESLint 0 error、vitest 全绿（含 UTC/Asia-Shanghai 双时区），新增纯逻辑模块单测覆盖率：核心分支 ≥ 90%。
- **NFR-2 性能**：推荐/洞察计算在 5000 笔流水规模下单次执行 < 20ms（中端机）；输入补全防抖 ≥ 250ms，不引起输入掉帧。
- **NFR-3 深色模式**：所有新增/改动界面在浅色与深色模式下对比度达标（正文 ≥ 4.5:1），无未适配硬编码色。
- **NFR-4 国际化**：新增可见文案 100% 走 i18n key，zh-CN/en-US 两份资源同步齐备。
- **NFR-5 可访问性**：可点元素最小触控尺寸 40×40dp，图标按钮带 aria-label/label，动效尊重 prefers-reduced-motion。
- **NFR-6 兼容**：minSdk 24；旧基座（无语音插件方法）上应用不崩溃；Web 端全部功能除语音外可用。
- **NFR-7 发版**：含原生插件，发整包 APK（versionCode 95）+ 热更 zip 同传，update.json 标记 requireApk=true、minNativeVersion=4.12.0。

## Constraints
- **Technical**：不引入服务端；语音仅用系统识别通道；视觉改动限制在现有令牌/组件类体系内；状态管理沿用 Zustand 各 slice 模式；持久化沿用现有 localStorage 封装。
- **Business**：记账关键路径（首页一句话秒存、底部 + 按钮）步数不得增加；任何预测错误都必须可被用户一键手动纠正。
- **Dependencies**：Capacitor 8 兼容的语音识别插件（实现初期做兼容性 spike 并记录结论）；Android 设备语音服务（部分无 GMS 设备可能不可用，需降级）；v4.11.0 已建立的 JDK21 + SDK36.1 构建环境。

## Assumptions
- 用户授权麦克风后，系统语音识别在主流国行/国际版 Android 上可用；不可用设备通过降级策略处理，不阻塞版本。
- 历史流水即推荐依据，无需用户额外配置或标注。
- 现有预算数据（budgets slice）可直接被洞察引擎读取。
- 洞察阈值（30%/5 倍/8 笔/±5% 金额近似/3 月中 2 月）为首版经验值，后续可调参；参数集中为常量便于调整。

## Acceptance Criteria

### AC-1: 推荐引擎纯函数正确性
- **Type**: `rule`
- **Given**: 一组构造的历史流水（含不同分类频率、近期/远期、同商家不同分类）
- **When**: 调用 recommender 的高频分类、上下文分类预测、账户推荐、常用金额函数
- **Then**: 输出排序与预期构造一致，且历史商家命中分类时 `parseSmartInputWithHistory` 返回的分类为历史高频分类
- **Pass Condition**: 新增单测全部通过（含上述用例），`npm run test` 双时区全绿
- **Evidence**: vitest 输出 + `src/utils/recommender.test.ts`/smartParser 相关用例

### AC-2: 记账页智能预选与快捷金额
- **Type**: `rule`
- **Given**: 有历史流水的用户进入新增记账页
- **When**: 页面加载
- **Then**: 分类网格按高频顺序排列且首位有"常用"标识；分类与账户被预选为推荐值；金额区可见常用金额 chips，点击填入金额；手动选择后预选不再被覆盖
- **Pass Condition**: 上述行为逐项可在设备/浏览器复现
- **Evidence**: 手动测试记录 + 相关组件代码审查

### AC-3: 智能输入补全候选
- **Type**: `rule`
- **Given**: 历史中存在备注"星巴克咖啡"等流水
- **When**: 在首页输入框键入前缀（如"星巴"）
- **Then**: 250ms 防抖后出现包含该前缀的历史文本候选，点击整条填入输入框
- **Pass Condition**: 候选出现、前缀过滤正确、点击填入正确
- **Evidence**: 手动测试记录

### AC-4: 连续记账行为
- **Type**: `rule`
- **Given**: 用户在新增记账页填好一笔支出
- **When**: 点击"保存并继续"
- **Then**: 流水保存成功、页面不跳转、金额与备注清空、分类重置为推荐预选、账户与收支类型保留、日期为今天、出现保存成功反馈，可立即记下一笔
- **Pass Condition**: 连续保存 3 笔均入账且字段状态符合预期
- **Evidence**: 手动测试记录 + store 数据核对

### AC-5: 洞察引擎规则正确性
- **Type**: `rule`
- **Given**: 构造数据集分别触发环比异常、预算超支、预计超支、大额支出、固定订阅、高频消费六类规则（含数据不足不触发的对照集）
- **When**: 调用 insights 生成函数
- **Then**: 仅应触发的规则出现，类型/严重级别/金额与构造预期一致；数据不足对照集不产出该类洞察
- **Pass Condition**: `src/utils/insights.test.ts` 用例全部通过
- **Evidence**: vitest 输出

### AC-6: 洞察在月报区的展示与跳转
- **Type**: `rule`
- **Given**: 当月存在触发洞察的数据
- **When**: 用户打开"我的"页并展开月度报表
- **Then**: 展示智能洞察卡片（图标+级别色+标题+描述+金额），点击固定/大额类洞察可跳到关联流水筛选；无洞察时显示克制空态
- **Pass Condition**: 各类型至少一次真机/浏览器复现，跳转筛选正确
- **Evidence**: 手动测试记录

### AC-7: 语音记账端到端（支持设备）
- **Type**: `rule`
- **Given**: 具备语音服务并授予麦克风权限的 Android 设备，安装 v4.12.0 整包
- **When**: 在首页点麦克风，说出"午餐 35 块 支付宝"后停止
- **Then**: 识别文本进入一句话输入框并经解析预填（金额 35/餐饮/支付宝账户），用户确认后入账；权限首次申请与拒绝路径均正常
- **Pass Condition**: 至少一台真机端到端通过；权限拒绝有引导且不崩溃
- **Evidence**: 真机录屏/测试记录

### AC-8: 语音降级
- **Type**: `rule`
- **Given**: Web 环境 / 旧基座无插件方法 / 设备无语音服务 三种场景
- **When**: 打开首页与记账页
- **Then**: 麦克风入口隐藏或禁用并带说明，其他记账功能完全正常，无控制台未捕获异常
- **Pass Condition**: 三场景逐一验证通过
- **Evidence**: 浏览器 + 旧基座安装包验证记录

### AC-9: 工程质量门禁
- **Type**: `rule`
- **Given**: 全部改动完成
- **When**: 执行 check/lint/test
- **Then**: tsc 0 错误、ESLint 0 error、vitest 双时区全绿；改动面内无死代码（NumericKeypad 已删）
- **Pass Condition**: 三条命令 exit code 均为 0
- **Evidence**: 命令输出

### AC-10: 全站视觉一致性与深色模式品质
- **Type**: `rubric`
- **Dimension**: 跨页面视觉一致性、层级/间距/状态统一、深色模式完整度
- **Scale**: 1-5
- **Anchors**: 1 = 页面间风格割裂、存在硬编码色、深色下多处刺眼/不可读；3 = 主要页面统一但次级页面或空/加载态粗糙；5 = 全部页面在两套模式下层级清晰、状态完整、观感统一精致
- **Pass Threshold**: >= 4
- **Evidence**: 浅色+深色双模式逐页截图走查（含加载态/空态/弹层）

### AC-11: 记账操作效率与可纠正性
- **Type**: `rubric`
- **Dimension**: 高频记账路径的点击/耗时，以及预测错误时的纠正成本
- **Scale**: 1-5
- **Anchors**: 1 = 推荐增加干扰或关键路径变长；3 = 预测可用但纠正平均需 2 次以上操作；5 = 常见场景预选即对、一键保存，错误时单次点击即可纠正
- **Pass Threshold**: >= 4
- **Evidence**: 典型场景（餐饮/打车/工资）手动计时走查 + 交互审查

### AC-12: 整包发布物
- **Type**: `rule`
- **Given**: 功能与验证全部完成
- **When**: 执行 v4.12.0 发版
- **Then**: versionCode 95 / versionName 4.12.0 的 APK 与热更 zip、update.json（requireApk=true,minNative=4.12.0）同传 GitHub Release，代码推送 main
- **Pass Condition**: Release 三资产可下载、APK aapt 信息正确、main 已更新
- **Evidence**: gh release 资产列表 + aapt badging + git 记录

## Open Questions
- [ ] 语音插件选型：优先 `@capacitor-community/speech-recognition`，若其不兼容 Capacitor 8 则改用维护中的等价分叉；实现初期 spike 后在任务记录中定论。
- [ ] 固定/订阅识别命中后是否提供"一键转为周期记账模板"动作？（默认：仅展示洞察不自动转换，避免与 v4.13.0 周期引擎耦合；若实现成本低可作为加分项）
- [ ] "保存并继续"的具体交互形态（并列双按钮 vs 主按钮旁小开关）在 UI 设计阶段按紧凑原则确定，需保证主保存按钮仍最醒目。
